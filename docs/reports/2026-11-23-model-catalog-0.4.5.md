# TaskPin 0.4.5 · PP-OCRv6 tiny 与模型文件夹验收

日期：2026-11-23。基线为0.4.4 / `23ec6c2`，最终源码以v0.4.5标签为准。

## 最终行为

新增随包提供的 **PP-OCRv6 tiny**，两份ONNX权重合计6,319,431字节（约6.0 MiB），沿用此前实测的检测长边960与4个推理线程。原v4/v5和自定义模型继续可选，升级保留已有选择；便签识别和截图翻译共用。

点击“设置 → 截图翻译 → 本地 OCR → 打开模型目录”，在 `app/ocr-models` 每个直接子文件夹放一组匹配的兼容ONNX检测/识别模型，重启或刷新后自动出现选项。原生Paddle导出和未知未来网络不保证直接兼容。文件命名、支持家族和可选model.json示例见[模型指南](../OCR-MODELS.md)。

发现过程在后台子进程中读取有限元数据；保存时才后台计算权重哈希并实际加载。取消、草稿变化、描述文件新增、目录成员变化都会使旧校验失效，不会保存未经当前校验的选择。替换权重产生新缓存身份；删除/重命名所选模型会明确报错，不静默回退。异常或过深嵌套的描述文件只令该模型不可用，正常模型保持可选。

## 真实模型与目录测试

三组内置模型分别运行英文、中文、深色技术文字生成图，检查实际文本、坐标和原始置信度。worker测试覆盖v5/v4/v6切换、连续复用、取消与自定义配置。

目录行为测试在程序编译后才复制规范命名的真实权重文件，开启新helper进程扫描并识别；验证不需要手写配置或重新编译。覆盖目录新增、重新打开/新进程发现、无效/不完整/重复模型、描述损坏、嵌套描述隔离、声明哈希错误、移走所选模型、同位置替换导致实际模型身份变化。另用真实PP-OCRv6 small模型对验证放入文件夹后发现与加载。生成中文/深色文字也经过文件夹模型识别。

设置测试先复现v6/目录按钮缺失、worker未传模型目录、校验后新增描述文件和校验后新增冲突ONNX仍被保存，再实现修复并保留回归。目录元数据最多读取65个即时成员，防止在界面线程扫描大量文件或哈希大型权重。

此前用户提供的清晰英文文档截图在本次正式helper上本机复验，720个参考字符经空白归一化后全部一致；图片与原文没有进入公开源码或CI。此前独立选型实验中，同机统一参数v6 tiny连续识别中位数约0.556秒、v5约2.685秒，调参后tiny约0.148秒、进程冷启动约1.435秒。该数据仅为此前单图实验，不是本次构建的通用性能保证；设备、文本和背景会改变耗时与结果。

## 发行与升级约束

运行时随包提供全部六份固定SHA256权重、catalog代码、依赖与许可证；构建与打包门禁必须实际加载三组内置模型。便携ZIP只带 `ocr-models/README.txt`，不携带开发者/用户外加的模型。升级脚本保留现有模型文件夹并逐项核对原文件哈希；任务、每日状态、设置/Key、历史和自启动另行核对。

以上证明应用逻辑、原生离屏渲染及本机模型行为，不能覆盖所有实体显示器、显卡、第三方热键抢占和未来模型网络。任意ONNX不是兼容性保证，技术符号仍应核对原图。完整运行时、模型来源和许可证见[OCR说明](../../TaskPinQt/ocr/README.md)与[运行时声明](../../licenses/PADDLEOCR_RUNTIME_NOTICE.md)。
