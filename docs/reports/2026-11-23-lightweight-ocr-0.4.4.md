# TaskPin 0.4.4 · 内置 PaddleOCR 轻量模型

日期：2026-11-23。基线：0.4.3 / `20edd51`。版本以 `v0.4.4` 标签为准。

## 如何使用

打开 **设置 → 截图翻译 → 本地 OCR**，选择 **PP-OCRv4 mobile · 轻量 · 14.9 MiB**，点击保存。便签识别与 F1 选区翻译共用该选择；取消保留原配置。两组模型已完整随包提供，无需额外下载、安装 Python 或手写 JSON。原有 v5 / 自定义模型选择在升级时保留。

默认仍是 PP-OCRv5 mobile，可随时切换。模型选择随每个请求进入应用级共享 worker，切换时重新加载对应权重；连续使用同一模型可复用，空闲释放与取消逻辑沿用 0.4.3。

## 模型体积与来源

| 模型 | 检测＋识别权重字节 | MiB | 用途 |
|---|---:|---:|---|
| PP-OCRv5 mobile | 21,450,882 | 20.5 | 默认中英文识别 |
| PP-OCRv4 mobile | 15,603,475 | 14.9 | 可选轻量模型 |

v4 权重体积约减少 **27.3%**。这是模型文件的对比，完整软件包因同时包含两组模型而增加约 14.9 MiB 未压缩权重；没有测量峰值内存。速度与识别质量需要按具体图片选择。

四份 ONNX 权重均来自 RapidOCR v3.10.0 对 PaddleOCR 模型的转换，使用现有 ONNX Runtime CPU 执行。下载地址、实际字节和 SHA256 均固定在 [runtime-lock.json](../../TaskPinQt/ocr/runtime-lock.json)；v4 哈希与该版本 RapidOCR 官方注册表一致。版权与 Apache-2.0 声明见 [运行时声明](../../licenses/PADDLEOCR_RUNTIME_NOTICE.md)。构建器、离线自检和打包门禁必须实际校验并加载两组模型；模型缺失或损坏会明确失败，不静默换模型。

## 同机耗时

同一 Windows 11 x64 电脑、默认双线程 CPU、相同生成中英文图片，按 v5 / v4 顺序分别启动独立 worker。每组保留一次冷启动和三次连续识别，连续列取中位数；采样期间没有编译或其他模型测试。进程耗时包含 IPC、首次启动和模型加载，没有调用翻译网络。冷启动仅一次，样本规模有限。

| 图片 | v5 首次 | v4 首次 | v5 连续中位数 | v4 连续中位数 |
|---|---:|---:|---:|---:|
| 两行中英文 | 2.348 秒 | 2.922 秒 | 1.263 秒 | 1.383 秒 |
| 六行中英文段落 | 2.318 秒 | 2.908 秒 | 1.149 秒 | 1.327 秒 |

**本次 v4 更小，但没有更快。** 因此保留 v5 默认值，将 v4 作为用户可选模型。该结果不能推广到所有设备、字体、背景和文字长度。固定模型顺序与单次冷启动也限制比较；没有据此给出通用速度或准确率承诺。原始生成内容、实际识别文字、模型身份、分阶段耗时见 [benchmark.json](2026-11-23-lightweight-ocr/benchmark.json)。

## 实际验收

新增功能先在旧实现失败：设置找不到轻量选项、选择无法保存、helper 拒绝 `profileId`。实现后完成：

- 两组真实模型的英文、中文、深色技术文字识别，检查实际文本、坐标与置信度。
- 真实 worker 的 v5 → v4 → v4 复用 → v5 → 自定义模型切换；元数据和模型身份对应所选权重。
- 设置保存、重新打开与取消，保留原配置；便签和翻译共用入口。
- 两组权重被篡改或缺失、未知/非法 profileId、同时指定自定义路径与内置 ID 时拒绝请求。
- F1 选区经过真实 v4 OCR → 明确标记的离线 Mock 翻译 → 可移动贴图；保留位置与缩放，云端服务不在 CI 中调用。
- 基准测试工具的单次进程与共享 worker 均使用当前选择，防止报告错误标记模型。

最终本地 **CTest 5/5**：截图 59、集成 48、体验 30、翻译/模型 59、画布 18，共 **214 passed / 0 failed / 0 skipped**；应用自检 **53/0**。真实模型行为测试单独运行，未跳过。

**Playwright Test 11/11**，一次约 39.4 秒。测试调度器调用真实 Qt 原生夹具与模型，覆盖上述流程以及 100% / 125% / 150% / 200% 显示缩放、快捷键和对照窗；没有浏览器替身或桌面鼠标/系统输入模拟。GitHub Actions 分支与标签发行执行同一门禁，云端报告、实际发行包和升级检查随发行附件提供。工作流不会使用用户 Key 调用付费服务。

以上验证应用逻辑与离屏渲染，未覆盖全部实体显卡、显示器或第三方软件抢键。技术符号需对照原图；模型体积不能代替识别质量评估。完整便携包需保留 `ocr/`，升级保留用户数据目录。
