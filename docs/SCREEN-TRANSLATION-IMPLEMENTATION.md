# 独立截图翻译实施记录

用户规范见 [SCREEN-TRANSLATION-SPEC.md](SCREEN-TRANSLATION-SPEC.md)。沿用现有 C++17 / Qt 6.4.3 / MinGW 11.2.0；不迁移到 Python。用户选择现有 DeepSeek / OpenAI 兼容文本服务，授权自动进行实现与测试。

## 交付范围

- 新入口“截图翻译”，Ctrl+Alt+T；独立选区、OCR、结果窗口和配置，F1 区域截图与便签逻辑保留。
- 本机 Windows.Media.Ocr 适配器输出行/坐标/语言；引擎不提供置信度时明确标记未知。截图通过子进程标准输入在内存中传递，不创建输入 PNG 或识别内容文件。
- 单栏阅读顺序、段落恢复、代码/公式绕过、HALCON 标识/路径/数值占位符保护与严格返回校验。
- 本地 OCR、明确标识的离线 Mock、DeepSeek/OpenAI 兼容文本服务；纯文本结果对照、缩略图、复制、置顶、取消、重试、重新截图。
- 云端仅接收用户授权的文本，授权绑定具体接口地址；独立 Windows 凭据存储，不把新密钥写入 JSON。现有 AI 配置仅由用户主动导入。
- 单任务与 task_id 隔离，异步 OCR/网络、超时、响应上限、受控一次块级修复，不堆积收费请求；取消或关闭后旧结果失效。

## 与推荐新项目技术栈的差异

现有应用已使用 Qt 捕获和 Windows OCR。首版采用独立的 Windows OCR 适配器复用系统能力，无需引入 Python、ONNX、模型下载或新运行库。必须用英文/中英混排/暗色虚构图案验证。OCR 置信度未知及语言包要求直接显示；不将其描述为 RapidOCR。若实际质量不足，后续通过适配器引入经锁定/许可核验的 OCR 模型。

MVP 为规范 P0–P3 与便携交付。静态译文覆盖、复杂表格/双栏恢复、本地翻译模型、历史与持久化缓存属于后续阶段；界面明确显示原图供关键公式核对。

## 顺序与验收

1. 独立工作树、配置/凭据/数据契约，文本布局与保护单元测试。
2. 内存 OCR、独立选区/结果窗口与任务控制器；验证反向拖动、DPR/负坐标、取消与原流程隔离。
3. Mock 和单一 HTTP 兼容适配器；localhost 测试鉴权、网络/超时、429、截断、缺块、重复 ID、占位符、取消迟到响应、隐私默认关闭。
4. 全套回归、Windows 原生虚构样本 OCR 探针、打包后独立自检、版本文档与发行附件核验。本轮不调用真实付费服务，不用私人截图做 fixture。

性能目标按实测报告，不能把目标写成结果。Windows 10、全部物理多屏、真实付费接口与复杂版面保留明确未验证项。
